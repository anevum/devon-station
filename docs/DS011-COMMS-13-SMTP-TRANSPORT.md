# DS011-COMMS-13 — SMTP submission transport, source-only

This module is a disconnected, injected Purelymail SMTP transport. It is **not** wired to the Worker entrypoint, an HTTP endpoint, an email Send button, a scheduled job or any live provider. It requires `claimDelivery(deliveryId)` to return an atomically claimed, owner-approved outbox record with trusted registry, sender, draft and delivery date. No such production outbox exists yet.

Submission validates the existing verified-send identity using the same pure MIME encoder, then requests a server-owned app password. It uses only `smtp.purelymail.com:465`, Cloudflare Workers `connect` with `secureTransport:'on'`, strict bounded multiline SMTP replies, EHLO with advertised AUTH PLAIN, fixed MAIL FROM/RCPT TO, one DATA transaction, and no plaintext or port fallback. Credentials and response text are never returned. Missing claim, unverified sender, malformed replies, failed recipient and invalid data fail closed; all sockets are closed. A connection loss after starting DATA is reported as `smtp_delivery_uncertain` rather than retried: an accepted `250` response may have been lost. Delivery `250` is a submission receipt, not proof of final recipient delivery.

Tests exercise synthetic TLS socket streams only. Local Node 22 ran 10/10 focused transport tests with the actual MIME encoder and temporary stub implementations of its registry/draft dependencies. This does not replace the entire repository, exact-head GitHub Actions, Cloudflare workerd, live TLS certificate/provider verification or real owner approval acceptance. Purelymail's published settings list SMTP port 465 with implicit TLS and full-address app-password login. Cloudflare Workers TCP socket documentation restricts outgoing port 25, not 465.

**Release NO-GO:** no live credentials, mail database migration, SMTP send, owner approval, DNS/MX, Cloudflare Access change, Anevum forwarding or production app release was performed. Before activation implement a durable owner-scoped, one-time CAS outbox claim and delivery-state journal (including uncertain outcomes), privacy-safe retention/encryption and backup/restore, authorized real Purelymail test, verified provider sender identity, exact-head CI, signed owner/browser acceptance, and separately approved production deployment. Never automatically retry an uncertain delivery.
